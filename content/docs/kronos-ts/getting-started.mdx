In this tutorial you build the smallest useful Kronos application: a tool store that adds tools, rents them out, refuses a rental when the tool is already out, and keeps an inventory you can query. Everything is in one file and runs in memory, and the tutorial takes about ten minutes. You need [Bun](https://bun.sh), which Kronos is built and tested on first, or Node.js 22 or later, and no prior knowledge of Kronos.

One file keeps the parts of Kronos in view. Once you have finished here, read the [guides](/docs/kronos-ts/guides), which show how we recommend organizing an application of your own, with one folder per feature.

## Create the project

Create a directory, install Kronos and a schema library, and create `main.ts`. Kronos accepts any [Standard Schema](https://standardschema.dev) library; this tutorial uses zod.

## Declare the messages

A Kronos application has three kinds of message: commands request a change, events record a change that happened, and queries request data. Each is declared once, as a descriptor with a name and a payload schema:

```ts
const ns = withNamespace("toolstore")

const AddTool = ns.command("AddTool", {
  payload: z.object({ toolId: z.string(), name: z.string() }),
  result: z.object({ ok: z.literal(true) }),
})

const ToolAdded = ns.event("ToolAdded", {
  payload: z.object({ toolId: z.string(), name: z.string() }),
  tags: { toolId: (payload) => payload.toolId },
})
```

`withNamespace("toolstore")` gives every message the qualified name `toolstore.<Name>`. A command's `result` is what its handler returns to the caller. An event's `tags` name the ids the event is about; Kronos selects the events a decision depends on by tag, as described under [Tags](/docs/kronos-ts/messages#tags).

Renting can be refused, so its result lists the refusal: `{ ok: false }` with a `rejection` code and the facts behind it. The event a rental records is about both the tool and the customer, so it carries both tags:

```ts
const RentTool = ns.command("RentTool", {
  payload: z.object({ toolId: z.string(), customerId: z.string() }),
  result: z.union([
    z.object({ ok: z.literal(true) }),
    z.object({ ok: z.literal(false), rejection: z.literal("TOOL_UNAVAILABLE"), toolId: z.string() }),
  ]),
})

const ToolRented = ns.event("ToolRented", {
  payload: z.object({ toolId: z.string(), customerId: z.string() }),
  tags: { toolId: (payload) => payload.toolId, customerId: (payload) => payload.customerId },
})
```

The inventory is a query, with the rows it returns as its result:

```ts
const GetInventory = ns.query("GetInventory", {
  payload: z.object({}),
  result: z.array(z.object({ toolId: z.string(), name: z.string(), available: z.boolean() })),
})
```

## Decide

A command handler loads the state it needs to decide, then appends events. A **state** is a fold over events: an initial value, and one function per event type that changes it. `Tool` records whether a tool has been added and who has rented it:

```ts
const Tool = state({
  id: { toolId: z.string() },
  tags: (id) => ({ toolId: id.toolId }),
  evolve: [
    (): { added: boolean; rentedBy: string[] } => ({ added: false, rentedBy: [] }),
    [ToolAdded, (tool) => ({ ...tool, added: true })],
    [ToolRented, (tool, { payload }) => ({ ...tool, rentedBy: [...tool.rentedBy, payload.customerId] })],
  ],
})
```

The two handlers load it. `ctx.load` reads the events tagged with the tool's id and folds them. `ctx.append` records an event when the handler returns, and only if no event matching what the handler loaded was stored in the meantime:

```ts
const addTool = commandHandler(AddTool, async ({ payload }, ctx) => {
  const tool = await ctx.load(Tool, { toolId: payload.toolId })
  if (!tool.added) ctx.append(ToolAdded, payload)
  return { ok: true }
})

const rentTool = commandHandler(RentTool, async ({ payload }, ctx) => {
  const tool = await ctx.load(Tool, { toolId: payload.toolId })
  if (tool.rentedBy.includes(payload.customerId)) return { ok: true }
  if (!tool.added || tool.rentedBy.length > 0) return { ok: false, rejection: "TOOL_UNAVAILABLE", toolId: payload.toolId }
  ctx.append(ToolRented, payload)
  return { ok: true }
})
```

A refusal is returned as the result, and nothing is appended. A command that already happened, such as a rental the customer already holds, returns `{ ok: true }` and appends nothing, so a caller can send it again after a timeout. [State and consistency](/docs/kronos-ts/state) explains the conditional append, and [Refuse a command](/docs/kronos-ts/guides/refusing-a-command) covers refusals.

## Keep an inventory

Event handlers react to events after they are stored, and a query handler returns what they wrote. This inventory is a `Map` in memory:

```ts
const inventory = new Map<string, { toolId: string; name: string; available: boolean }>()

const recordAddedTool = eventHandler(ToolAdded, ({ payload }) => {
  inventory.set(payload.toolId, { toolId: payload.toolId, name: payload.name, available: true })
})

const recordRentedTool = eventHandler(ToolRented, ({ payload }) => {
  const row = inventory.get(payload.toolId)
  if (row) inventory.set(payload.toolId, { ...row, available: false })
})

const getInventory = queryHandler(GetInventory, () => [...inventory.values()])
```

[Events](/docs/kronos-ts/events) and [Queries](/docs/kronos-ts/queries) describe these handlers.

## Assemble the application

`kronos()` connects each handler to the event store and the buses it uses, starts the event processor, and returns the running application. The processor reads the event log in order and calls the event handlers for each event:

```ts
const eventStore = inMemoryEventStore()
const commandBus = localCommandBus(unitOfWork)
const queryBus = localQueryBus(unitOfWork)
const inventoryView = eventProcessor("inventory-view", eventStore, inMemoryTokenStore(), unitOfWork)

const app = kronos({
  commandHandlers: [
    { ...addTool, eventStore, commandBus, queryBus },
    { ...rentTool, eventStore, commandBus, queryBus },
  ],
  eventHandlers: [
    { ...recordAddedTool, commandBus, queryBus, processor: inventoryView },
    { ...recordRentedTool, commandBus, queryBus, processor: inventoryView },
  ],
  queryHandlers: [{ ...getInventory, queryBus }],
})
```

Every store and bus here is in memory. [Assembly](/docs/kronos-ts/assembly) describes `kronos()`, and [Run on Postgres](/docs/kronos-ts/guides/running-on-postgres) replaces the stores with a database.

## Use it

`send` sends a command and returns its result, and `query` sends a query. The rest of the file adds two tools, rents the drill to Ada twice and then to Grace, waits until the inventory processor has handled every event, and prints the inventory:

```ts
for (const [toolId, customerId] of [["t-1", "ada"], ["t-1", "ada"], ["t-1", "grace"]] as const) {
  const outcome = await send(commandBus, RentTool, { toolId, customerId })
  console.log(`${customerId} rents ${toolId}: ${outcome.ok ? "rented" : outcome.rejection}`)
}
```
